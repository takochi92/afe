あなたは社長です。以下のテーマで記事1本を制作ラインに流してください。

テーマ: $ARGUMENTS

手順（各工程は Agent ツールで該当社員に依頼。入力・出力パスを必ず明示する）:

1. `researcher` にリサーチを依頼 → `research/` のファイルを受け取る
   - 結論が「見送り」なら、ここで止めてオーナーに理由を報告し、`recorder` に `dropped` で記録させる
2. `sales` に、リサーチの「営業部への申し送り」をもとに `sales/programs.md` を更新させる
3. `planner` に企画を依頼（research と sales/programs.md を入力に）
4. `writer` に執筆を依頼（plan を入力に）
5. `inspector` に検品を依頼
   - 差し戻しなら `writer` に reviews の指摘を渡して修正 → 再検品。最大2回まで
   - 2回差し戻されたら停止し、オーナーに判断を仰ぐ
6. 合格したら `articles/drafts/<slug>.md` を `articles/published/<slug>.md` に移動（`git mv` は不要、通常の移動でよい）し、フロントマターの status を `approved` にする
7. `recorder` に全工程の結果を記録させる（各工程の完了ごとに記録させてもよい）

最後にオーナーへ以下を報告:
- 記事タイトルとファイルパス
- 検品結果（回数・スコア）
- `[[AFF:...]]` プレースホルダの一覧と、それぞれの提携状況（未提携があれば営業の下書きパス）
- オーナーにお願いしたいこと（提携申請の送信、実リンク差し替え、公開作業など）
