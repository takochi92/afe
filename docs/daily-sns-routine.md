# 毎日のSNS自動投稿ルーティン（Threads）

オーナーの許可（2026-10-11、チャットで直接）：Threadsへの自動投稿と、その流れすべて（画像の作成・公開リポジトリへの保存・投稿・記録）。
範囲は、このファイルの手順と `docs/threads-automation.md` のルールの内側に限る。それ以外（リンクの掲載、他のSNS、有料の操作、アカウント設定の変更）は、オーナーに確認する。

## 手順（社長が、毎朝の起動で行う）
0. 準備
   - `takochi92/afe-assets`（公開、画像置き場）を `add_repo`（push）で追加し、`/home/user/afe-assets` にクローンする
   - `records/posts.csv` を読み、今日（日本時間）すでに何件投稿したかを数える。**1日の上限は2件**。上限なら何もせず終了
   - 日付が **2026-12-01 以降**なら、トークンの期限が近い（約60日、2026-12-10ごろ切れる）ことを、会社サイトの進行ボードに「オーナーが作り直す」タスクとして出す（`tasks` に追加。すでにあれば重複させない）
1. 題材を決める（リサーチ部の資料から）
   - `research/` の事実だけを使う。価格・期限・制度は「YYYY年MM月時点」を付ける
   - すでに投稿した内容（`records/posts.csv`）と重ならないようにする
   - 題材の例：こどもNISAの手続き・条件・よくある疑問（祖父母、兄弟、親の口座、ジュニアNISAとの違い）。書くのは**制度と手続きの説明まで**。個別商品の推奨や利回りの断定は禁止
2. 作る（執筆部）
   - 投稿文：200字以内。結論を先に。誇張や断定は使わない
   - 図解画像（任意）：`node scripts/make_card.js <出力.png> '<JSON>'`。出力は作業用の場所（scratchpad）に置く
   - キャラクター（うさぎ・りす＝教わる側、ふくろう博士＝教える側）の会話カードを使える。使い方は `docs/characters.md`。**ライセンスの確認が済むまでは、キャラ画像を公開しない**（オーナーに確認する）
   - 色はオーナーの指示（2026-10-11）で、既定を**黄色×赤のポップ配色**（`theme: pop`）にした。落ち着いた配色は `theme: calm`
   - 目を引く工夫は、色・大きな数字・「知ってた？」のような問いかけまで。**「緊急」「やばい」「お得」など、事実の裏づけがない煽りは使わない**（景品表示法・金融の広告ルール）
3. 検品（検品部）
   - `inspector` に、`docs/compliance.md` の基準で投稿文と画像を確認させる
   - **合格したものだけ**が次へ進む。不合格なら直して再検品（最大2回）。それでも不合格なら、その日は投稿しない
4. 投稿
   - `scripts/threads_post.sh "<投稿文>" [画像.png]`
   - 失敗したら、同じ内容を再投稿しない（二重投稿を避ける）。`records/posts.csv` で投稿済みかを確認し、原因を会社サイトに報告する
5. 記録（記録部）
   - `records/posts.csv` は、スクリプトが追記する。`records/activity-log.md` に1行追記する
   - 会社サイトの `staff` / `tasks` を更新する（社員の状態と `updatedAt`、今日の投稿を完了にして `doneAt` を入れる）。`activity` に、いつ・誰が・何をしたかを1件ずつ追加する
6. 変更をコミットして、ブランチ `ccr-622bec71-djrqes` にプッシュする

## 止める条件
- トークンの確認が通らない（`GET /v1.0/me` がエラー）→ 投稿せず、会社サイトにエラーを報告
- 検品で2回不合格 → その日は投稿しない
- 迷う内容（規約や法令の判断、新しい種類の操作）→ 投稿せず、オーナーに確認

## 会社サイトへの返事（オーナーの指示、2026-10-11）
- 指示に対する返事は、**チャットより先に**、会社サイトのデータベース `orders/<id>` の `reply` に書く（ページの指示ログに出る）
