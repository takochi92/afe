# Instagram 自動投稿の流れ

最終更新: 2026-10-11 ／ 状況: **接続済み・投稿開始**（2026-10-11に2本投稿。オーナーが全般許可）

## 0. 毎日の自動起動（2026-10-12から）
- 朝 8:37・昼 12:37・夜 20:37（日本時間）の3回、定期の起動がカルーセルを作って投稿する（検品に合格したものだけ。1日の上限は3件。1回の起動で1件）
- 追加の手動投稿は原則行わず、各回で当日件数を確認して重複・上限超過を防ぐ

## 1. 全体の流れ（ひと目で）

```
【最初に1回だけ】 オーナーが準備 ─→ 接続テスト ─→ テスト投稿（チャットで許可）─→ 自動投稿を開始

【毎日（自動）】
 題材を選ぶ → 台本（枚数と各枚の文言）→ 画像を作る → 検品に合格？ ─┬─ はい → 公開用リポジトリに画像を保存 → Instagramに投稿 → 記録
  （リサーチ資料の事実だけ）  （2〜10枚）  （JPEG・4:5）  （検品部）   └─ いいえ → 直して再検品（2回まで）。だめなら、その日は投稿しない
```

## 2. 役割分担
| | オーナー | 私たち（社長・各部署） |
|---|---|---|
| 最初の準備 | アカウントの切り替え、Metaの設定、投稿用の鍵の発行、環境への登録 | 手順の案内、接続テスト、テスト投稿 |
| 毎日 | なし（会社サイトで状況を見るだけ） | 台本・画像・検品・投稿・記録のすべて |
| 例外 | 新しい種類の操作（リンク掲載、広告、アカウント設定の変更）の許可 | 迷う内容は投稿せず、会社サイトで確認を求める |

## 3. 最初の準備（オーナー）
すでにあるアプリ「Flysheep」（Threads用）に、Instagramを足す。**手順はMetaの画面が変わることがあるため、止まったら画面を送ってもらえれば案内する。**
1. Instagramのアカウントを作る → 設定で **プロアカウント**（「クリエイター」か「ビジネス」）に切り替える
2. Meta for Developers の「Flysheep」→「ユースケース」→「Instagram」を追加（Instagram APIの設定。Instagramログインを使う方式）
3. 許可（アクセス許可と機能）に、次の2つを追加して「テスト準備完了」にする
   - `instagram_business_basic`（基本情報）
   - `instagram_business_content_publish`（投稿）
4. 「アプリのロール」→ ロール → **Instagramテスター** にそのアカウントを追加 → Instagramアプリで招待を承認（「設定」→「ウェブサイトの許可」付近）
5. 設定画面の「トークンを生成」で、**長期のアクセストークン**を作る（約60日で切れる）。**チャットに貼らない**
6. 環境の設定（Threadsのときと同じ場所）
   - 「許可されたドメイン」に `graph.instagram.com` を追加
   - 「ネットワークシークレット」に追加: 名前 `INSTAGRAM_ACCESS_TOKEN`、種類 Bearer、許可ウェブサイト `graph.instagram.com`、ヘッダー Authorization / Bearer
7. 新しいセッションで「Instagramのトークンを登録した。docs/instagram-flow.md を読んで、接続テストをして」と送る

## 4. 毎日の流れ（私たち）
| 手順 | 担当 | 内容 | 出力 |
|---|---|---|---|
| ① 題材 | リサーチ／社長 | `posts/queue/INDEX.md` か、研究資料から。事実の範囲だけ | 題材 |
| ② 台本 | 編集部 | 5〜8枚。下の「カルーセルの作り方」に従う。キャプション（2,200字以内）も書く | `posts/ig/<日付>-<番号>.md` |
| ③ 画像 | 社長 | `node scripts/make_carousel.js <フォルダ> '<JSON>'` | `slide-01.jpg …`（JPEG、4:5） |
| ④ 検品 | 検品部 | 法令・事実・誤字・はみ出しを、全枚で確認 | `reviews/` |
| ⑤ 保存 | 社長 | 画像を公開リポジトリ `takochi92/afe-assets` の `images/<日付>/` に保存（Instagramが画像をURLで取りに来るため） | 公開URL |
| ⑥ 投稿 | 社長 | `scripts/instagram_post.sh "<キャプション>" <画像…>` | 投稿URL |
| ⑦ 記録 | 管理部 | `records/ig_posts.csv`、業務日誌、会社サイトの「社員の動き」 | 記録 |

## 5. 画像の枚数について（結論：複数枚にする）
- Instagramは、1枚より **複数枚（カルーセル）** のほうが、見返される・保存されやすい形式。解説系の投稿に向く
- まず **5〜6枚** で始める。上限は10枚（投稿APIの上限）。枚数ごとの成果は、**保存数・リーチ・プロフィールへの移動数**を記録して、週ごとに比べる（当社のデータがまだないため、効果の数字は置かない）
- Threadsも複数枚の投稿ができる（上限20枚）。**同じ画像を、Threads・Instagramの両方に使える**

## 6. カルーセルの作り方（ルール）
- **1枚目＝フック**：問いかけと数字（「こどもNISA 事前申込、知ってた？」）。「緊急」「やばい」「お得」などの煽りは使わない
- **2〜（最後の手前）枚目＝1枚に1ポイント**：大きな見出し＋1〜2文。キャラ（うさぎ・りす＝質問、ふくろう博士＝答え）のひとこと
- **最後の1枚＝まとめ＋「保存して、あとで見返してね」**
- **全枚に、時点・元本割れのリスクの注記**（フッターに自動で入る）
- 言い切らない（「〜とされています」）。個別の商品・会社をすすめない。リンクは載せない（キャプションのURLは押せない）
- 画像の規格：**JPEG**、縦横比 4:5（1080×1350）。1投稿は2〜10枚

## 7. 投稿のしくみ（API）
`scripts/instagram_post.sh` が行う。**まだ一度も動かしていない（鍵がないため）。最初の接続テストで確認する。**
1. 各画像について「子コンテナ」を作る（`image_url`、`is_carousel_item=true`）
2. 子の idを `children` に並べて「カルーセルのコンテナ」を作る（`media_type=CAROUSEL`、`caption`）
3. コンテナの処理が終わる（`status_code=FINISHED`）まで待つ
4. `media_publish` で公開する
5. 投稿のURL（permalink）を取得して記録する
- 制限（公式の説明にもとづく。**変わることがあるので、接続テストのときに確認する**）：24時間に投稿できる数の上限がある／キャプションは2,200字まで／画像は公開URLで渡す
- 1枚だけの投稿は、子を作らず、`image_url` と `caption` で1回作って公開する

## 8. 失敗したとき
- 画像のURLが読めない → 数秒待って再確認。だめならその日は投稿せず、原因を会社サイトに報告
- コンテナが `ERROR` → 画像の規格（JPEG・比率）を確認して作り直す。**同じ内容を二重に投稿しない**（投稿前に `records/ig_posts.csv` を確認）
- トークンが切れた → オーナーが作り直して登録（約60日ごと。会社サイトに予定を載せる）
