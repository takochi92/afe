# マイ金庫 Chrome拡張（v0.3.1）

`tools/vault`（Web版）と同じ金庫を Chrome から使う拡張です（Manifest V3）。
- フェーズ1：ポップアップで解錠し、ログインフォームに自動入力
- フェーズ2：パスワードの保存提案（Chrome標準の保存ダイアログの代わり）と、パスキーの保存・サインイン。金庫への書き込み（PUT）を始めました
- v0.3.0：インライン入力（ログイン欄にフォーカスすると、入力欄の下に候補を表示）
- **v0.3.1（今回）**：インライン入力を、`<form>` を使わないログイン画面にも広げた

## v0.3.1 の変更点：フォーム無しのログイン画面
- 欄とボタンが JavaScript で結ばれた、`<form>` の無いログイン画面（例：REDSTONE）でも候補を出します
- 欄がフォームに属さない場合は、祖先を最大8階層たどり、**有効なパスワード欄をちょうど1つ含む最小のコンテナ**（ログインクラスタ）を入力の範囲にします。パスワード欄が0、または最小のコンテナで2つ以上なら出しません
- さらに、フォーム無しの場合は、**実際に入力される2欄（パスワード欄と、その直前のテキスト欄）にフォーカスしたときだけ**出します。クラスタがページ全体（`body`）のような広い範囲になったときに、検索欄など無関係な欄で候補が出るのを防ぐためです
- フォームに属する欄は従来どおり（そのフォームが範囲。パスワード欄2つ以上は対象外）。安全条件（ロック中は項目情報なし、入力直前の照合の再検証、表示はタイトルとユーザー名のみ、https の最上位フレームのみ）も変わりません

## v0.3.0 の変更点：インライン入力
- 対象：https ページの最上位フレームで、**パスワード欄がちょうど1つのフォーム**の中のテキスト／メール／パスワード欄（v0.3.1 からフォーム無しの画面も対象。上記参照）。パスワード欄が2つ以上のフォーム（登録・変更画面）、金庫サーバー自身のページでは出しません
- フォーカスすると、そのサイトに一致する項目（完全一致 → 同じ登録ドメイン）を入力欄の直下に出します。表示は**タイトルとユーザー名だけ**で、パスワードは出しません。閉じた Shadow DOM なので、ページのCSSの影響を受けません
- 候補をクリックすると（本物の操作 `isTrusted` のみ）、background が復号して**その場で照合をやり直し**、一致した場合だけユーザー名とパスワードを content script に渡します。入力はポップアップの「入力」と同じ `content.js`（ネイティブの value セッター＋ `input`／`change` イベント）で、そのフォームの中だけに入れます
- フォーカスが外れる、Esc、スクロール、ウィンドウのサイズ変更で閉じます。再表示は次のフォーカス時
- **ロック中**は候補の中身を一切出さず、「🔒 金庫がロック中です。ツールバーのアイコンから解錠してください」の1行だけを出します（background もロック中は項目の情報を返しません）
- 追加したメッセージ：`inlineList`（候補の id・タイトル・ユーザー名）、`inlineFill`（選ばれた項目の資格情報）。どちらもページ専用で、照合には Chrome が付けた送信元タブのURLを使います
- 権限の追加はなし。既存の `content_scripts` に `content.js` を `detect.js` より先に読み込むよう加えただけです（範囲は同じ `https://*/*`）。外部通信も従来どおり金庫サーバーのみ

## フェーズ2の変更点
### A. パスワードの保存提案
- **金庫サーバー自身のページ（設定したサーバーURLと同じオリジン）は保存提案の対象外**です。金庫ページで入力したマスターパスワードや同期トークンが提案・保存されることはありません。ポップアップでも、そのタブでは「このサイトの項目」を出しません（修正：2026-11）
- https のページでログイン・登録の**送信**（フォーム送信、送信ボタン、パスワード欄での Enter）を検知し、ページ右上に「金庫に保存しますか？」を出します。同じサイト＋同じユーザー名の項目があれば「パスワードを更新しますか？」、同じパスワードなら何も出しません
- 送信されなかった入力欄や、空のパスワードは保存しません。確認欄つきの登録フォームでは、確認欄と一致する値を新パスワードとします。2段階ログイン（ユーザー名→パスワードの順の画面）は、10分以内の直前のユーザー名を使います
- 送信直後に画面が切り替わっても、次のページで提案を出します
- **金庫がロック中**なら、提案を保留キュー（`chrome.storage.session`）に積み、ページには「保留しました」とだけ表示します。拡張を解錠すると、ポップアップにまとめて表示されます（1時間で期限切れ）
- 保存は「GET で最新を取得 → 項目をマージ（`mt` を更新）→ PUT（`If-Match`）」。409 が返ったら取り直してマージし直し、1回だけ再試行します。Web版の合流（項目ごとに `mt` が新しい方）とも整合します

### B. パスキー
- ページの `navigator.credentials.create/get`（`publicKey` のときだけ）を包み、「パスキーを金庫に保存しますか？」「金庫のパスキーでサインイン」を出します。どちらも「ブラウザ標準を使う」を選べます
- 作成時：ES256（P-256）の鍵ペアを拡張の中で作り、公開鍵と credentialId をサイトへ返します（attestation は `none`）。**金庫への保存（PUT）が成功してから**サイトに返します
- サインイン時：rpId が一致する金庫のパスキーを選ばせ、解錠済みのときだけ署名します。authenticatorData は WebAuthn どおり（RP ID の SHA-256、フラグ UP・UV・BE・BS、署名カウンタ 0）。UV は「金庫の解錠」を根拠に立てます
- rpId がページのオリジンに合わない場合（WebAuthn の規則：有効ドメインそのもの、または登録ドメイン以上の上位ドメイン。公開サフィックス単体や IP は不可）、ES256 を受け付けないサイト、条件付き要求（`mediation: "conditional"`：入力欄のオートフィル）、iframe 内の要求は、**包まずにブラウザ標準へそのまま渡します**
- 金庫がロック中は「解錠したので再確認／ブラウザ標準を使う／キャンセル」を出します。金庫にそのサイトのパスキーがなければ、何も出さずブラウザ標準に渡します
- **attestation を必須とするサイト（一部の銀行・企業向けサービスなど）では使えないことがあります。** その場合は「ブラウザ標準を使う」を選んでください
- 秘密鍵・復号した項目は背景処理（service worker）の中だけで扱い、ページ側（`page.js`）には渡しません。ページに渡るのは WebAuthn の応答（公開鍵・署名など、本来サイトに返すもの）だけです
- 項目形式：`{id, kind:"passkey", title, rpId, credentialId(base64url), privateKey(pkcs8 base64), publicKey(spki base64), userHandle(base64), userName, userDisplayName, created, mt, del}`
- ポップアップの「すべての項目」にパスキーも表示され、削除できます（サイト側の登録は別途削除してください）。Web版では「パスキー（編集は拡張でのみ）」と表示されるだけで、点検の対象外です

## 仕様の要点
- 暗号は Web版と同一（PBKDF2-SHA256 60万回 → AES-256-GCM）。既存の金庫データをそのまま開けます
- 通信先は金庫サーバーだけ（`GET /vault` と、保存時の `PUT /vault`）。第三者への通信・解析・外部ライブラリはなし
- マスターパスワードは保存しません。解錠中の鍵は `chrome.storage.session`（ディスクに書かれず、ブラウザ終了で消える）にだけ置き、自動ロック（既定10分、設定で1〜120分）で消します
- 端末に保存するのは、サーバーURL・同期トークン・暗号文のキャッシュ（`chrome.storage.local`）。キャッシュは暗号文のままで、サーバーに繋がらないときの表示用です
- 自動入力の `content.js` は従来どおり、「入力」を押した時だけ注入します
- 権限: `activeTab` / `scripting`（入力）、`storage`（設定）、`alarms`（自動ロック）。通信許可は既定のサーバー1つだけで、別のURLを設定した時にそのサーバー1つだけを、設定画面の保存ボタンで許可します

## 権限が増える理由と影響（フェーズ2）
| 追加 | 理由 | 影響 |
|---|---|---|
| `content_scripts`：`detect.js`（`https://*/*`、`document_start`、最上位フレーム） | フォーム送信の検知と、提示UIの表示、パスキー要求の中継 | **全https サイトで常駐**します。Chrome の表示は「すべてのウェブサイトのデータの読み取りと変更」になります。読むのは送信時の入力欄の値だけで、外へは送りません（拡張本体へ渡し、金庫サーバーにだけ暗号化して保存） |
| `content_scripts`：`page.js`（同上、`world: "MAIN"`） | `navigator.credentials` をサイトのスクリプトより先に包むため | ページのスクリプトと同じ世界で動きます。秘密情報は持たせていません |

- 依頼では MAIN world 用に `web_accessible_resources` を使う想定でしたが、**使っていません**。代わりに manifest の `"world": "MAIN"`（Chrome 111以降）で直接注入しています
  - `<script src="chrome-extension://…">` での注入は読み込みが非同期で、サイトが先に `navigator.credentials` を使ってしまうことがある
  - `web_accessible_resources` があると、どのサイトからでも拡張の存在を検出できる
- 上記以外の権限は増やしていません。content script からのメッセージは、Chrome が付けた送信元オリジンだけを信用し、rpId や保存提案の照合に使います。ポップアップ専用の操作（保留一覧・パスキー削除）は、拡張のページからしか受け付けません
- 提示UIは閉じた Shadow DOM で、ボタンは本物のユーザー操作（`isTrusted`）だけを受け付けます
- 入力してよいのは **https のページ**（開発用に localhost の http も可）。押した瞬間にもう一度、現在のタブのURLと項目が一致するか確認します
- 照合は、完全一致 → 同じ登録ドメイン（`login.example.com` ↔ `example.com`、`co.jp` 等も考慮）の順。`github.io` 等の共有ドメインは別サイト扱い

## 読み込み手順
1. このブランチを取得し、`tools/vault-extension/` の場所を確認する
2. Chrome で `chrome://extensions` を開く
3. 右上の **デベロッパーモード** をオン
4. **パッケージ化されていない拡張機能を読み込む** → `tools/vault-extension/` フォルダーを選ぶ
5. ツールバーのパズルのアイコンから「マイ金庫」をピン留めする
6. 拡張の **設定**（ポップアップ右上の ⚙）で、サーバーURL（初期値 `https://desktop-8ern2im.tail0cdc77.ts.net`）と同期トークンを入力 → **保存** → **接続テスト**で「接続OK」を確認
   - 初期値と違うURLにすると、保存時に「このサイトへのアクセス」の許可を求められます（そのサーバー1つだけ）

## 動作確認の手順
前提: Tailscale に接続済み、Web版にログイン情報が1件以上ある（例: URLが `https://example.com`）。
1. **解錠**: ポップアップでマスターパスワードを入力 → 項目が表示される。間違ったパスワードでは「マスターパスワードが違います」
2. **照合**: 登録済みサイトのログインページを開いてポップアップを開く → そのサイトの項目が上に表示される
3. **自動入力**: 「入力」を押す → ユーザー名とパスワードが入る（2段階ログインの場合は、ユーザー名の画面で1回、パスワードの画面でもう1回押す）
4. **一致なし**: 登録のないサイトでポップアップを開く → 「一致する項目がありません」と、コピー用ボタンだけの一覧が出る
5. **http のページ**: http のページでは「入力」が出ず、コピーのみになる
6. **自動ロック**: 設定で自動ロックを1分にして解錠 → 1分以上あけてポップアップを開くとロック画面に戻る。🔒ボタンでも即ロック
7. **保存提案（解錠中）**: 登録のないサイトでログイン → 右上に「金庫に保存しますか？」→「保存する」→ Web版で開くと項目がある
8. **更新**: 同じサイト・同じユーザー名で違うパスワードを送信 → 「パスワードを更新しますか？」。同じパスワードなら何も出ない
9. **保留キュー**: 🔒でロックしてからログイン → 「保留しました」と出る → ポップアップのロック画面に「保存の提案が N 件」→ 解錠すると一覧が出て保存できる
10. **パスキー作成**: パスキーに対応したサイト（例: テスト用に https://webauthn.io ）で登録 → 「パスキーを金庫に保存しますか？」→「金庫に保存」→ 登録完了。ポップアップの一覧に「（パスキー）」が出る
11. **パスキーでサインイン**: 同じサイトでパスキーでサインイン → 「金庫のパスキーでサインイン」→ アカウントを選ぶ → サインイン成功
12. **ロック中のパスキー**: ロックした状態で 11 → 「金庫がロック中です」→ 解錠して「解錠したので再確認」で続行できる。「ブラウザ標準を使う」で Chrome 標準の画面に切り替わる
13. **素通し**: パスキー非対応や attestation 必須のサイトで「ブラウザ標準を使う」が機能すること
14. **インライン入力**: 登録済みサイトのログイン欄をクリック → 欄の下に「🔐 タイトル／ユーザー名」が出る（パスワードは出ない）→ クリックで両欄に入る → ログインできる（React 等のサイトでも入力が認識されること）
15. **インライン入力（閉じる）**: 候補が出た状態で Esc／別の場所をクリック／スクロール → 閉じる
16. **インライン入力（フォーム無し）**: REDSTONE（redstoneonline.jp）など `<form>` を使わないログイン画面で、ID欄・パスワード欄のどちらにフォーカスしても候補が出て、クリックで両欄に入る。同じページの検索欄など、関係ない欄では出ない
17. **インライン入力（対象外）**: 登録のないサイトでは何も出ない。登録・パスワード変更画面（パスワード欄2つ）では出ない。ロック中は「金庫がロック中です」の1行だけ
18. **オフライン**: Tailscaleを切ってポップアップを開き、解錠 → 「端末内のキャッシュを表示中」と出て、項目が見える
19. **同期**: Web版で項目を追加 → ポップアップの ⟳ で反映される

## ヘッドレス検証（フェーズ2、本物の server.py と Web版、テスト用ページ）
テスト時だけ、検証用コピーの manifest に `http://localhost/*` を足して実施（本体の manifest は https のみ）。
- 保存提案：送信→次のページで提案→保存 → Web版で開ける。送信していない入力欄・空のパスワードは保存されない。同じ値は提案なし、違う値は「更新」
- 保留キュー：ロック中に送信 → ロック画面に「1件」→ 解錠後のポップアップから保存
- 409：GET と PUT の間に別端末の書き込みを割り込ませる → 2回目で成功し、両方の項目が残る（重複なし）
- パスキー：作成（`instanceof PublicKeyCredential`、type・origin・challenge、RP IDハッシュ、フラグ `0x5D`、authData 内の credentialId、alg -7、fmt none）→ サインイン（ページ側で、返された公開鍵で署名を検証して成功、フラグ `0x1D`（UV あり）、userHandle 一致）
- rpId 不一致はブラウザ標準へ素通し（標準の SecurityError）。ロック中は案内 → キャンセルで NotAllowedError
- Web版：パスキー項目は「パスキー（編集は拡張でのみ）」と表示、点検で落ちない。Web版で別の項目を編集保存しても、拡張が保存した項目・パスキーは残る

## ヘッドレス検証（v0.3.0 インライン入力）
テスト用のログインフォーム（ページ側で全要素の文字色・サイズを `!important` で上書きしたもの）と金庫の項目で実施。
- フォーカス → 候補「Test Login / inline@test.jp」を表示（パスワードは表示に含まれない）→ クリック → 両欄に入力され、`input`・`change` が両欄で発火。入力後に候補は出直さない
- パスワード欄へのフォーカスでも候補が出る。Esc・フォーカスが外れたときに閉じる
- ロック中は「金庫がロック中です」の1行のみ。background の `inlineList` もロック中は `{locked:true}` だけを返す
- 一致する項目がないサイト（別ホスト）では何も出ない。パスワード欄が2つのフォームでは出ない
- 再検証：ページの content script から、別サイトの項目の id で `inlineFill` を送っても `{ok:false}`（資格情報は返らない）
- フェーズ2の検証（保存提案・保留キュー・409・パスキー・金庫ページの除外）も再実行し、従来どおり
- スクロールで閉じる動作は、ヘッドレスでは確認していない

## ヘッドレス検証（v0.3.1 フォーム無し）
- フォーム無しのログインページ（div で囲んだID欄＋パスワード欄＋JSのリンクボタン）：フォーカス → 候補表示 → クリック → 両欄に入力され、`input`・`change` が両欄で発火。同じページのサイドバーの検索欄では候補が出ず、検索欄に値も入らない
- フォーム無しで同じ div にパスワード欄が2つ：出ない
- 回帰：フォーム型（表示・入力・Esc・フォーカスが外れたとき）、パスワード欄2つのフォームの除外、ロック中の1行表示、一致なしサイト、別サイトの項目idでの `inlineFill` 拒否、すべて従来どおり

## 既知の制限
- パスワードをコピーしたあとの20秒クリア消去は、ポップアップを開いたままの場合だけ働きます（閉じるとタイマーも消えるため）。確実に消したい場合は、入力ボタンを使ってください
- iframe 内（別オリジン）のログインフォームには入力しません。Shadow DOM 内の入力欄も未対応です
- 自動ロックの時間は「最後に解錠・コピー・入力した時刻」から数えます
- 保存提案の検知は一般的なフォーム向けです。独自の仕組みで送信するサイトでは出ないことがあります
- 保留キューの中身（ユーザー名・パスワード）は、解錠されるまで `chrome.storage.session` に平文で置かれます（ディスクには書かれず、ブラウザ終了か1時間で消えます）
- インライン入力は、`<form>` の中の欄か、フォーム無しなら「パスワード欄を1つだけ含む近いまとまり（8階層以内）」の中のID欄・パスワード欄が対象です。ID欄とパスワード欄が離れた場所にある画面、ID欄がパスワード欄より後ろにある画面、iframe 内や Shadow DOM 内のログイン欄では出ないことがあります。その場合はポップアップの「入力」を使ってください
- 公開サフィックスの判定は簡易版です（`co.jp`・`github.io` などの主なものに対応）
- 署名カウンタは常に 0（同期型パスキーと同じ扱い）
- 第三者による監査は受けていません
